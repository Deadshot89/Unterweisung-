# v0.36.1 Auth Preview Fix Design

## Goal
Ensure the signed-in Azure Static Web Apps preview renders the same professional UI as the anonymous/seed fallback view and actually recognizes the signed-in Entra user.

## Root causes
1. `staticwebapp.config.json` currently lives at repository root while the Static Web Apps workflow deploys `frontend` with `skip_app_build: true`. Azure Static Web Apps expects the config file inside the deployed app/output directory, so the routing/auth configuration is not reliably included.
2. The browser calls a separate Azure Function App domain through `frontend/config.js`. Static Web Apps authentication only injects `x-ms-client-principal` into the Static Web Apps integrated API. A standalone Function App request does not automatically receive the Static Web Apps user principal.

## Approved architecture
- Keep the frontend and API code unchanged functionally, but deploy the existing `api` directory as the Static Web Apps integrated API for the preview/application.
- Switch the frontend API base URL to same-origin (`''`) so requests go to `/api/...` through the Static Web Apps host.
- Put `staticwebapp.config.json` in `frontend/staticwebapp.config.json` so it is part of the deployed artifact.
- Keep static application assets reachable during the login flow. Protect application/API data with authenticated routes rather than allowing CSS/JS requests to be redirected as login pages.
- Preserve the standalone Function App workflow for now; it is not deleted in this hotfix.

## User-visible result
- After Microsoft sign-in the header must show the actual signed-in user rather than `Nicht angemeldet / Seed-Fallback`.
- The signed-in page must retain the complete v0.36 visual design.
- The application remains v0.36.x; hotfix release is `v0.36.1` / package `0.36.1`.

## Constraints
- No database schema changes.
- No permission-model changes.
- No CSS workaround that duplicates the base stylesheet.
- No client-forged identity headers.
- No removal of the current standalone Azure Function deployment during this hotfix.
