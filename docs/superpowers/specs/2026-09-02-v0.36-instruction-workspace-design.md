# v0.36.0 Instruction Workspace Design

## Goal
Transform the Unterweisungen view from a tall text-heavy table into a compact professional management workspace while preserving all existing business logic, permissions, Azure APIs, template handling and test-question handling.

## Problem
In v0.35.2 the complete instruction description is rendered directly inside the first table column. Long descriptions therefore make single rows hundreds of pixels high. The remaining columns become visually detached, action buttons are cramped at the right edge, and scanning 60+ instruction types is inefficient. The same generic table treatment is also too loose in several administrative views.

## Approved direction
Use a compact overview plus detail/edit workspace (Option B). The overview optimizes scanning; full descriptions and management controls move out of the row and into the selected-instruction detail area.

## Scope
1. Rebuild the `Unterweisungen` view as a compact workspace.
2. Keep search and add filters for category, status, template state and test-question state.
3. Add summary metrics for total/active instructions, missing templates and missing active test questions.
4. Keep instruction rows compact. Show name, category, interval, template state, question count, status and one primary action. Long descriptions are truncated to a short preview and must never determine row height.
5. Add a selected-instruction detail panel with the full description, metadata and management actions.
6. Keep create/edit form, template management and test-question management, but arrange them as clear workspace sections rather than one endless unstructured page.
7. Apply safe density improvements to shared administrative tables/forms without changing their data or API behavior.
8. Improve desktop and responsive behavior so action controls do not disappear outside the visible area.

## Architecture
The existing `instruction-type-management-v23.js` remains the owner of instruction business UI logic. Its rendering functions are refactored directly instead of being replaced by a second override layer. A new `professional-suite-v36.css` contains visual rules for the compact instruction workspace and conservative shared table/form density improvements. `frontend/index.html` loads the new stylesheet and shows v0.36.0.

No permanent `MutationObserver`, polling render loop or DOM rewrite loop may be introduced. Rendering remains event-driven through the existing `renderInstructions`, `setView` and data-loading flow.

## Instruction overview
The top workspace area contains:
- page title and company context;
- search field;
- category filter;
- status filter: all / active / inactive;
- template filter: all / assigned / missing;
- questions filter: all / available / missing;
- metric chips/cards: total, active, without template, without active questions.

The table uses a stable compact row. The description preview is limited to one or two lines via CSS and the full text is available in the detail panel.

Columns:
- Unterweisung
- Bereich
- Intervall
- Unterlage
- Testfragen
- Status
- Aktion

The action column contains one primary `Öffnen` or `Bearbeiten` action rather than several full-width buttons. Secondary actions are located in the detail panel.

## Detail/edit workspace
Selecting an instruction stores its id in transient frontend state and renders a detail section beneath the overview. It shows:
- instruction name;
- full description/content;
- category;
- recurrence interval;
- assigned template and file name;
- active test-question count;
- active/inactive status;
- buttons for edit, template upload/open and activate/deactivate according to permissions.

Editing continues to use the existing form fields and API calls. Existing authorization from `canEditInstructionTypes()` remains authoritative.

## Templates and questions
Template upload/list and test-question management remain functionally unchanged. Their cards receive clear section headings and spacing so the page reads as distinct management zones. No Azure Blob, API route or database changes are required.

## Shared design improvements
`professional-suite-v36.css` may make conservative changes to shared administrative tables/forms:
- smaller vertical cell padding;
- stronger column alignment;
- stable action-cell sizing;
- buttons may wrap inside action areas instead of forcing table width;
- text cells use sensible line-height and overflow handling;
- mobile/tablet tables retain horizontal scrolling instead of clipping content.

These rules must not alter the dashboard shell, navigation or business logic.

## Responsive behavior
Desktop: overview and detail use the available content width beside the left navigation.
Tablet: filters wrap into multiple rows; action controls remain reachable.
Mobile: metrics and filters stack; the table can scroll horizontally; detail/form sections become one column.

## Performance constraints
- No continuous MutationObserver.
- No recurring render timer.
- Search/filter events trigger only the instruction view render needed for the interaction.
- Loading test questions must keep the existing guarded asynchronous behavior and must not create a render loop.

## Versioning
Visible application and package version become exactly `v0.36.0` / `0.36.0`.

## Testing
Automated checks must verify:
- new stylesheet is loaded;
- visible version is v0.36.0;
- compact overview/filter functions exist;
- detail selection exists;
- full description is no longer the unrestricted row body;
- existing save/edit/toggle/template/test-question integrations remain present;
- no MutationObserver or interval-based render loop is added to the v0.36 workspace;
- the full existing `npm test` suite passes.

## Non-goals
- No database schema changes.
- No Azure API changes.
- No permission model changes.
- No redesign of the dashboard/navigation shell.
- No removal of existing instruction, template or test-question functionality.
